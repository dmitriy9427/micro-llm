## 1. Зачем нужен Rust

JavaScript и Python **интерпретируются**: программа читается и выполняется на лету, а за вас работает сборщик мусора (он сам освобождает память). Это удобно, но медленно.

Rust **компилируется** в машинный код заранее, как C и C++. Результат работает почти на предельной скорости процессора. При этом, в отличие от C++, Rust не даёт сделать типичные ошибки с памятью: компилятор отказывается собирать опасный код. Сборщика мусора нет, а утечек и «висящих» ссылок тоже нет.

Цена — компилятор строгий, и сначала он будет часто ругаться. Это нормально: сообщения об ошибках в Rust подробные и обычно подсказывают исправление.

Где это используют: части браузера Firefox, Discord, ядро Linux, инструменты фронтенда (SWC, Rolldown, Biome). Вы, скорее всего, уже пользуетесь Rust-программами, даже не зная об этом.

## 2. Установка и инструменты

Нужно три вещи:

- **`rustup`** — установщик и менеджер версий (как `nvm` для Node).
- **`cargo`** — менеджер пакетов и сборщик в одном (как `npm` + `vite`).
- **`rustc`** — сам компилятор; вы запускаете его через `cargo`, напрямую почти никогда.

Установка:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustup target add wasm32-unknown-unknown     # цель для браузера (WebAssembly)
cargo --version
```

Если установщик пишет «could not amend shell profile» (нет прав на `~/.bash_profile`), запустите его с флагом `-s -- -y --no-modify-path`, а `~/.cargo/bin` добавьте в `PATH` вручную.

Соответствие понятий:

| JavaScript | Rust |
|---|---|
| `package.json` | `Cargo.toml` |
| `package-lock.json` | `Cargo.lock` |
| `node_modules` | `target/` (сборка) и `~/.cargo` (скачанные пакеты) |
| `npm install x` | `cargo add x` |
| `npm run build` | `cargo build --release` |
| `npm test` | `cargo test` |
| пакет в npm | «крейт» (crate) на crates.io |

Флаг `--release` включает оптимизации. Без него сборка быстрее, но программа в десятки раз медленнее. Для замеров скорости всегда используйте `--release`.

Файл `src/main.rs`:

fn main() {

## 4. Переменные и типы

В Rust **типы статические**: у каждой переменной тип известен при компиляции, как в TypeScript, но проверяется строже и без `any`.

```rust
let a = 5;            // как const, менять нельзя
let mut b = 5;        // mut = mutable, менять можно (как let)
b += 1;
let c: u32 = 10;      // тип можно указать явно
```

Главное отличие от JS: **по умолчанию всё неизменяемо**. Хотите менять — пишите `mut`. Это защищает от случайных правок.

Основные типы:

| Rust | Что это | В JS |
|---|---|---|
| `u8`, `u32`, `u64` | целое без знака (0, 1, 2…), число — размер в битах | `number` |
| `i32`, `i64` | целое со знаком | `number` |
| `f32`, `f64` | дробное | `number` |
| `usize` | целое под размер памяти, для индексов и длин | `number` |
| `bool` | true / false | `boolean` |
| `String` | строка, которой владеет переменная (её можно менять) | `string` |
| `&str` | ссылка на кусок строки (только чтение) | `string` |
| `Vec<T>` | растущий массив одного типа | `Array` |
| `(u32, u32)` | кортеж фиксированной длины («пара») | `[a, b]` |
| `HashMap<K, V>` | словарь | `Map` |

В нашем коде пара токенов — это `(u32, u32)`, а `type Pair = (u32, u32);` — просто короткое имя для неё (как `type Pair = [number, number]` в TypeScript).

Типы чисел не смешиваются сами: `u32` нельзя сложить с `u64`, нужно явно написать `x as u64`. Поначалу раздражает, но предотвращает целый класс багов.

## 5. Функции, структуры и методы

**Функция:**

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b          // без точки с запятой — это возвращаемое значение
}
```

Последнее выражение без `;` — результат функции (можно и `return a + b;`).

**Структура** (аналог класса, но только с данными):

```rust
struct Point { x: f64, y: f64 }

impl Point {                          // методы живут в блоке impl
    fn new(x: f64, y: f64) -> Point { // «конструктор» — обычная функция
        Point { x, y }
    }
    fn len(&self) -> f64 {            // &self — «смотрю на себя, но не меняю»
        (self.x * self.x + self.y * self.y).sqrt()
    }
}

let p = Point::new(3.0, 4.0);
println!("{}", p.len());              // 5
```

- `Point::new` — функция типа (в JS это был бы `static`).
- `&self` — метод читает объект; `&mut self` — метод меняет объект; просто `self` — метод забирает объект себе (см. следующий раздел).
- Наследования в Rust нет. Общее поведение описывают **трейтами** (traits) — они похожи на интерфейсы TypeScript. Для чтения нашего кода они почти не нужны.

В нашем `lib.rs` структура `Tokenizer` хранит слияния, словарь и кэш, а в `impl Tokenizer` лежат её методы: `train`, `encode`, `decode`.

## 6. Владение и заимствование: главная идея Rust

Это самое непривычное место. Стоит понять один раз — дальше будет проще.

**Правило:** у каждого значения в памяти есть ровно один **владелец** (переменная). Когда владелец выходит из области видимости, значение удаляется. Поэтому сборщик мусора не нужен: компилятор заранее знает, когда освобождать память.

```rust
let a = String::from("привет");
let b = a;                 // значение ПЕРЕЕХАЛО в b, a больше не владеет им
println!("{}", a);         // ОШИБКА: a уже пустая
```

В JS обе переменные указывали бы на одну строку. В Rust строка перешла новому хозяину («move»), и старой переменной пользоваться нельзя. Так исключаются ошибки «двух хозяев»: двойное освобождение, чтение удалённого.

**Заимствование.** Чтобы посмотреть на значение, не забирая его, берут **ссылку** `&`:

```rust
fn length(s: &String) -> usize { s.len() }   // только смотрим

let a = String::from("привет");
let n = length(&a);          // одолжили a на время вызова
println!("{} {}", a, n);     // a по-прежнему наша — работает
```

Два вида ссылок и главное правило:

- `&x` — читать можно, сколько угодно читателей одновременно;
- `&mut x` — читать и менять, но **только один** такой «менялка» в каждый момент, и в это время читателей нет.

Это похоже на «одного писателя или много читателей» в базах данных. Правило проверяется при компиляции, поэтому в Rust не бывает гонок данных.

**Копирование и клонирование.** Простые типы (`u32`, `bool`, пара `(u32, u32)`) копируются сами при присваивании. Для «тяжёлых» (`String`, `Vec`) нужно явно вызвать `.clone()`, это сделает полную копию. В нашем коде встречается `ids.clone()` и `word.to_string()` — именно когда нужна своя копия, например чтобы положить результат в кэш и одновременно вернуть его.

**Совет новичку:** если компилятор ругается на владение, часто помогает (1) взять ссылку `&` вместо передачи значения, или (2) вызвать `.clone()`. Оптимизировать можно потом.

## 7. Option и Result: никаких null и исключений

В Rust нет `null` и `undefined`, нет `try/catch`. Вместо них два перечисления.

**`Option<T>`** — «значение есть или его нет»:

```rust
let x: Option<u32> = Some(5);
let y: Option<u32> = None;

match x {
    Some(v) => println!("есть {}", v),
    None => println!("нет"),
}
```

`HashMap::get` возвращает `Option`: ключ может отсутствовать. Компилятор заставит вас обработать оба случая, поэтому ошибки `Cannot read property of undefined` в Rust невозможны.

**`Result<T, E>`** — «получилось или ошибка»:

```rust
fn parse(s: &str) -> Result<u32, String> {
    s.parse::<u32>().map_err(|e| e.to_string())
}
```

Удобные сокращения: `?` (если ошибка — вернуть её из функции), `.unwrap()` (достать значение или аварийно упасть — годится в тестах, в рабочем коде лучше избегать), `if let Some(x) = ... { }` (обработать только один случай).

В нашем `Tokenizer::train` возвращается `Result<Tokenizer, JsError>`: либо готовый токенайзер, либо ошибка, которая попадёт в JavaScript как исключение.

## 8. Коллекции и итераторы

```rust
let mut v: Vec<u32> = Vec::new();
v.push(1);
v.push(2);
let total: u32 = v.iter().map(|x| x * 2).sum();   // 6
```

`|x| x * 2` — это **замыкание** (стрелочная функция `x => x * 2`). Цепочки `.iter().map().filter().collect()` выглядят почти как в JS, но при компиляции превращаются в быстрый цикл без промежуточных массивов.

Полезные методы, которые мы используем:

| Rust | Что делает | В JS |
|---|---|---|
| `v.windows(2)` | все соседние пары `[v[i], v[i+1]]` | цикл `for (i…) [a[i], a[i+1]]` |
| `.filter_map(f)` | применить `f` и выкинуть пустые (`None`) | `.map(f).filter(Boolean)` |
| `.min_by_key(f)` | элемент с минимальным ключом | `reduce` по минимуму |
| `.max_by(cmp)` | элемент по функции сравнения | `reduce` по максимуму |
| `.zip(other)` | склеить два списка попарно | `a.map((x, i) => [x, b[i]])` |
| `.entry(key).or_insert(v)` | в словаре: взять значение или создать | `map.get(k) ?? map.set(k, v)` |
| `.collect()` | собрать итератор в `Vec`, `HashMap`… | `Array.from` |

Словарь `HashMap` по смыслу — `Map`: `insert`, `get`, `contains_key`. Порядок обхода у него **не гарантирован**, и это важный момент для нашего кода (см. разбор ниже).

## 9. Разбор нашего кода построчно

Файл `rust/bpe/src/lib.rs`. Идея алгоритма — в главе 3 учебника. Здесь — как она записана на Rust.

### 9.1. Шапка

```rust
use regex::Regex;
use std::collections::HashMap;
use wasm_bindgen::prelude::*;

type Pair = (u32, u32);
```

`use` — как `import`. Берём регулярные выражения, словарь и всё необходимое для WebAssembly. `Pair` — пара номеров токенов.

### 9.2. Разбиение на слова

```rust
fn pretoken_regex() -> Regex {
    Regex::new(r"\s?\w+|\s?[^\w\s]+|\s+").unwrap()
}
```

То же регулярное выражение, что и в Python: слово с пробелом перед ним, знаки, пробелы. Префикс `r"…"` — «сырая» строка, где `\` не нужно удваивать. `.unwrap()` — «выражение корректное, иначе пусть упадёт»; оно у нас написано вручную, так что падения быть не может.

### 9.3. Слияние пары в тексте

```rust
fn merge_ids(ids: &[u32], pair: Pair, new_id: u32) -> Vec<u32> {
    let mut out = Vec::with_capacity(ids.len());
    let mut i = 0;
    while i < ids.len() {
        if i + 1 < ids.len() && (ids[i], ids[i + 1]) == pair {
            out.push(new_id);
            i += 2;
        } else {
            out.push(ids[i]);
            i += 1;
        }
    }
    out
}
```

Это функция `_merge` из Python дословно. `ids: &[u32]` — «ссылка на срез»: мы читаем чужой массив, не забирая его (раздел 6). `Vec::with_capacity` заранее выделяет память нужного размера. Возвращаем новый вектор `out` (последняя строка без `;`).

### 9.4. Структура токенайзера

```rust
#[wasm_bindgen]
pub struct Tokenizer {
    merges: Vec<Pair>,
    rank: HashMap<Pair, u32>,
    vocab: Vec<Vec<u8>>,
    cache: HashMap<String, Vec<u32>>,
    pretoken: Regex,
}
```

- `#[wasm_bindgen]` — «атрибут»: пометка, что эту структуру нужно сделать доступной из JavaScript.
- `pub` — публичная (доступна снаружи модуля).
- Поля: список слияний по порядку; «ранг» каждой пары (чем меньше число, тем раньше пара была выучена); таблица «номер токена → его байты»; кэш уже разобранных слов; готовое регулярное выражение.

### 9.5. Обучение

```rust
pub fn train(text: &str, vocab_size: usize) -> Result<Tokenizer, JsError> {
```

Принимает ссылку на текст (не копирует гигабайты) и желаемый размер словаря. Возвращает `Result`: ошибку или токенайзер.

Сначала считаем слова и их частоты:

```rust
let mut index: HashMap<&str, usize> = HashMap::new();
let mut freq: Vec<u64> = Vec::new();
let mut pieces: Vec<Vec<u32>> = Vec::new();
for m in re.find_iter(text) {
    let w = m.as_str();
    match index.get(w) {
        Some(&i) => freq[i] += 1,
        None => { index.insert(w, pieces.len()); freq.push(1); pieces.push(w.bytes().map(u32::from).collect()); }
    }
}
```

`index` хранит «слово → его номер», `freq[i]` — сколько раз слово встретилось, `pieces[i]` — слово как список байт-токенов. Слова идут **в порядке первого появления** — это важно для совпадения с Python. `match` — это `switch` по `Option` (раздел 7).

Основной цикл — 768 раз:

```rust
let mut stats: HashMap<Pair, (u64, usize)> = HashMap::new();
// для каждой пары: (сколько раз встретилась, порядок первого появления)
```

Мы проходим по всем словам, считаем пары `windows(2)` и умножаем на частоту слова. Затем выбираем лучшую:

```rust
.max_by(|a, b| a.1 .0.cmp(&b.1 .0).then(b.1 .1.cmp(&a.1 .1)))
```

Читать так: «берём пару с наибольшим счётчиком; если счётчики равны — ту, что появилась раньше». Именно этот второй критерий делает результат одинаковым с Python. Без него `HashMap` отдавал бы пары в случайном порядке, и слияния отличались бы.

Затем: если лучшая пара встречается меньше 2 раз — останавливаемся; иначе запоминаем слияние и применяем его ко всем словам через `merge_ids`.

### 9.6. Кодирование слова

```rust
fn encode_word(&mut self, word: &str) -> Vec<u32> {
    if let Some(hit) = self.cache.get(word) { return hit.clone(); }
    let mut ids: Vec<u32> = word.bytes().map(u32::from).collect();
    while ids.len() >= 2 {
        let best = ids.windows(2)
            .filter_map(|w| self.rank.get(&(w[0], w[1])).map(|&r| (r, (w[0], w[1]))))
            .min_by_key(|&(r, _)| r);
        match best {
            Some((r, pair)) => ids = merge_ids(&ids, pair, 256 + r),
            None => break,
        }
    }
    self.cache.insert(word.to_string(), ids.clone());
    ids
}
```

1. Если слово уже разбирали, возвращаем копию из кэша.
2. Превращаем слово в байты.
3. Пока есть что склеить: среди соседних пар находим ту, у которой **наименьший ранг** (она выучена раньше всех), и склеиваем.
4. Когда склеивать больше нечего, кладём результат в кэш и возвращаем.

`&mut self` значит, что метод меняет объект (пополняет кэш). Поэтому `encode` тоже принимает `&mut self`.

### 9.7. Загрузка и сохранение

`from_json` читает тот же файл, что пишет Python: `{"kind":"bpe","merges":[[a,b],…]}`. Это важно: токенайзер, обученный на Python, можно использовать в Rust и наоборот. `to_json` пишет такой же файл.

## 10. WebAssembly: как Rust попадает в браузер

**WebAssembly (WASM)** — это компактный бинарный формат команд, который браузер умеет выполнять почти так же быстро, как родной код. Это не замена JavaScript, а дополнение: JS отвечает за страницу, WASM — за тяжёлые вычисления.

Путь от кода до страницы:

```
lib.rs ──cargo build──▶ microllm_bpe.wasm ──wasm-bindgen──▶ microllm_bpe.js + _bg.wasm ──▶ браузер
```

1. `cargo build --release --target wasm32-unknown-unknown` — компилирует Rust в `.wasm`. Цель `wasm32-unknown-unknown` значит «32-битная виртуальная машина, без операционной системы».
2. `wasm-bindgen` — утилита, которая по пометкам `#[wasm_bindgen]` создаёт файл `.js`-обёртку. Она переводит между мирами: JS-строку в Rust-строку и обратно, `Uint32Array` в `Vec<u32>`, `JsError` в настоящее исключение.
3. На странице:

```js
import init, { Tokenizer } from "./wasm/microllm_bpe.js";
await init();                           // скачать и подготовить .wasm
const tok = Tokenizer.train(text, 400); // вызов Rust из JS
```

**Что важно знать:**

- WASM и JS **не делят объекты**, только числа и память. Строки при каждом вызове копируются туда и обратно, поэтому дёргать WASM мелкими вызовами в цикле невыгодно. Лучше отдать большой кусок и получить большой результат — именно так работает наш `encode(text)`.
- Объекты на стороне Rust живут в памяти WASM, и сборщик JS их не освобождает. Когда токенайзер больше не нужен, вызывают `tok.free()` (в демо так и сделано).
- Файл `.wasm` у нас около 1 МБ, потому что регулярные выражения Rust знают таблицы Unicode. Для рабочей страницы это нормально.
- Профиль в `Cargo.toml` (`opt-level = 3`, `lto = true`, `panic = "abort"`) — настройки максимальной скорости и меньшего размера.

Кроме браузера, тот же `.wasm` можно запускать в Node.js и на сервере (Cloudflare Workers, Deno).

## 11. Шпаргалка: JS ↔ Rust

| Нужно | JavaScript | Rust |
|---|---|---|
| Константа | `const a = 1` | `let a = 1;` |
| Переменная | `let a = 1` | `let mut a = 1;` |
| Функция | `function f(x) { return x+1 }` | `fn f(x: i32) -> i32 { x + 1 }` |
| Стрелочная | `x => x * 2` | `\|x\| x * 2` |
| Массив | `[1, 2]` | `vec![1, 2]` |
| Добавить | `a.push(3)` | `a.push(3)` |
| Длина | `a.length` | `a.len()` |
| Цикл | `for (const x of a)` | `for x in &a` |
| Условие | `if (x) {}` | `if x {}` (скобки не нужны) |
| Строка шаблоном | `` `a ${b}` `` | `format!("a {}", b)` |
| Пустое значение | `null` | `None` |
| Ошибка | `throw new Error()` | `Err(...)` |
| Печать | `console.log(x)` | `println!("{:?}", x)` |
| Класс | `class A {}` | `struct A {}` + `impl A {}` |
| Импорт | `import x from "x"` | `use x::y;` |

`{:?}` в `println!` печатает «отладочный» вид любого значения, удобно для массивов и структур.

## 12. Частые ошибки компилятора

- **`borrow of moved value`** — вы использовали значение после того, как отдали его другому владельцу (раздел 6). Решение: передайте ссылку `&x` или вызовите `.clone()`.
- **`cannot borrow as mutable`** — вы пытаетесь менять то, что объявлено без `mut`, или есть другая ссылка. Решение: добавьте `mut` или сократите время жизни другой ссылки.
- **`mismatched types`** — смешали `u32` и `usize`, `&str` и `String`. Решение: `as usize`, `.to_string()`, `&s`.
- **`the trait bound … is not satisfied`** — тип не умеет чего-то нужного (например, сравниваться или печататься). Часто лечится `#[derive(Debug, Clone, PartialEq)]` над структурой.
- **`unused variable`** — это предупреждение, не ошибка; уберите переменную или назовите `_x`.

Главный приём: читайте сообщение целиком. Rust показывает, какая строка виновата, и часто пишет «help: …» с готовым исправлением.

## 13. Куда двигаться дальше
