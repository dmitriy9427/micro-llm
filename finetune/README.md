# Дообучение Qwen2.5-0.5B-Instruct (LoRA) на резюме

Вопрос: можно ли «вложить» знание о резюме прямо в веса модели, а не подкладывать фрагменты в промпт (RAG)?

```bash
python build_data.py          # 231 пример из фрагментов резюме (в т.ч. 24 отказа на посторонние темы)
python train_lora.py --epochs 2 --batch 2   # ~3 минуты на M4 Pro, bf16, ~1,7% параметров
python evaluate.py            # сравнение трёх вариантов на 33 вопросах, которых нет в обучении
```

## Результат (33 вопроса, жадная генерация, bf16)

| Вариант | Факты (24 вопроса) | Отказы на постороннее (9) |
|---|---|---|
| Qwen без контекста | 7 / 24 | 0 / 9 |
| Qwen + нужный фрагмент в промпте (RAG) | 20 / 24 | 0 / 9 |
| Qwen + LoRA, без контекста | 18 / 24 | 8 / 9 |

## Честные выводы

* **Стиль и границы модель выучила хорошо**: отказывается отвечать не по теме (8 из 9) — базовая не отказывалась никогда.
* **Факты выучила плохо, хотя метрика этого не показывает.** Метрика «в ответе есть нужное слово» мягкая. Среди ответов
  дообученной модели есть выдуманные детали: «Paraweb — Музыкальный визуализатор», «15+ лет в коммерческой разработке»,
  описание Прилавка с несуществующим «каталогом на удалении». Модель в 0,5 млрд параметров за 2 эпохи запомнила
  формат и обрывки, но не надёжные факты.
* **Для фактов лучше RAG**: ответ опирается на реальный текст, его можно проверить и обновить без переобучения.
  Дообучение стоит применять для формы ответа, тона и отказов, а не как хранилище знаний.
* Ошибки: 2+2 модель решила ответить (отказ не сработал), на вопрос про ИИ-проекты ответила «нет».
* Одна проверка, один запуск, без подбора гиперпараметров — это учебный эксперимент, не бенчмарк.

## Заметка про память

Первый запуск в fp32 упёрся в память и из-за подкачки замедлился с 0,7 с до 70 с на шаг. Веса в bf16 и батч 2 вернули
скорость: 232 шага за 166 с. Базовые варианты оценены в той же точности, чтобы сравнение было честным.
