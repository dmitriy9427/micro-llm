## 1. Что такое Python и как его запускать

Python — интерпретируемый язык, как JavaScript: код читается и исполняется на лету, компилировать вручную ничего не надо. Он медленнее Rust, но очень удобен, и именно на нём пишут почти весь машинное обучение: библиотеки PyTorch, transformers, NumPy.

Секрет скорости ML на Python: тяжёлые вычисления выполняет не сам Python, а библиотеки, написанные на C++/CUDA/Metal. Python только «командует» ими. Поэтому наша модель считается на видеочипе Apple (`mps`), хотя код на Python.

Запуск:

```bash
python3 --version                 # проверить, что он есть (нужен 3.9 или новее)
python3                           # интерактивная консоль, как в DevTools: можно вводить строки
python3 script.py                 # запустить файл (как node script.js)
python3 -c "print(2 + 2)"         # выполнить одну строку
```

Консоль (`python3` без аргументов) — лучший способ пробовать примеры из этого документа. Выход: `exit()` или Ctrl+D.

## 2. Окружение и пакеты: venv и pip

В JS пакеты лежат в папке проекта (`node_modules`). В Python по умолчанию они ставятся **в общую систему**, и разные проекты могут конфликтовать. Чтобы этого не было, делают **виртуальное окружение** (`venv`) — отдельную папку с собственным Python и пакетами для одного проекта.

```bash
python3 -m venv .venv                  # создать окружение в папке .venv
source .venv/bin/activate              # «войти» в него (в приглашении появится (.venv))
pip install -r requirements.txt        # поставить пакеты проекта
deactivate                             # выйти
```

Можно не активировать, а вызывать Python окружения напрямую — именно так в учебнике: `.venv/bin/python scripts/...`.

| JavaScript | Python |
|---|---|
| `package.json` | `requirements.txt` (список пакетов) или `pyproject.toml` |
| `node_modules` | `.venv/lib/python3.x/site-packages` |
| `npm install` | `pip install -r requirements.txt` |
| `npm install x` | `pip install x` |
| `npx` / `node` | `python` |

Наши зависимости: `torch` (PyTorch — нейросети), `numpy` (массивы чисел), `pytest` (тесты); для дообучения ещё `transformers` и `peft`.

## 3. Синтаксис: отступы вместо скобок

Главное отличие: **блоки кода задаются отступами**, а не фигурными скобками. Отступ — 4 пробела. Вместо `{` ставится двоеточие.

```python
# JavaScript:  if (x > 3) { console.log("много"); } else { console.log("мало"); }

x = 5
if x > 3:
    print("много")
else:
    print("мало")
```

Что ещё отличается:

- нет `;` в конце строк;
- нет `let`/`const`: переменная создаётся присваиванием `x = 5`;
- комментарии — `#`, а длинные описания в тройных кавычках `"""…"""` (в начале файла, функции, класса — это «докстринг», документация; в нашем коде ими начинаются все файлы);
- `true`/`false`/`null` пишутся `True`/`False`/`None` (с большой буквы);
- `&&`, `||`, `!` заменены словами `and`, `or`, `not`;
- сравнение на равенство — `==`, проверка на «пусто» — `x is None` (а не `== None`);
- `else if` пишется `elif`;
- возведение в степень — `**` (`2 ** 3` = 8), целочисленное деление — `//` (`7 // 2` = 3), обычное `/` всегда даёт дробь.

**Циклы:**

```python
for i in range(3):          # 0, 1, 2   (как for (let i = 0; i < 3; i++))
    print(i)

for name in ["a", "b"]:     # по элементам (как for...of)
    print(name)

for i, name in enumerate(["a", "b"]):   # с номером: (0, "a"), (1, "b")
    print(i, name)

while x > 0:
    x -= 1
```

`x++` в Python нет, пишут `x += 1`.

**Строки с подстановкой (f-строки)** — аналог шаблонных строк `` `a ${b}` ``:

```python
name = "Дима"
print(f"Привет, {name}! Дважды два = {2 * 2}")   # Привет, Дима! Дважды два = 4
```

В нашем коде они везде, например `print(f"шаг {step:5d} | обучение {loss:.3f}")`. Часть `:.3f` — формат: «дробное, три знака после запятой».

## 4. Типы данных и коллекции

Типы динамические, как в JS: тип у значения, а не у переменной.

| Python | Что это | В JS |
|---|---|---|
| `int` | целое (без ограничения размера!) | `number` / `BigInt` |
| `float` | дробное | `number` |
| `str` | строка | `string` |
| `bool` | `True` / `False` | `boolean` |
| `None` | «ничего» | `null` |
| `list` | изменяемый список `[1, 2, 3]` | `Array` |
| `tuple` | неизменяемый список `(1, 2)` | замороженный массив |
| `dict` | словарь `{"a": 1}` | объект / `Map` |
| `set` | множество уникальных значений `{1, 2}` | `Set` |

**Списки, срезы, распаковка:**

```python
a = [10, 20, 30, 40]
a[0]          # 10
a[-1]         # 40  — отрицательный индекс считает с конца
a[1:3]        # [20, 30] — срез: от 1 до 3 (3 не входит)
a[:2]         # [10, 20]
a[2:]         # [30, 40]
len(a)        # 4 (а не a.length)
a.append(50)  # добавить в конец (как push)

x, y = (1, 2)            # распаковка: x = 1, y = 2
first, *rest = a         # first = 10, rest = [20, 30, 40, 50]
```

**Словари:**

```python
d = {"имя": "Дима", "лет": 31}
d["имя"]                 # "Дима"
d.get("город", "—")      # безопасно: если ключа нет, вернёт "—"
d["город"] = "Москва"    # добавить
"имя" in d               # True — проверка ключа
for key, value in d.items():
    print(key, value)
```

**Списковые включения (comprehensions)** — компактная запись «пройтись по списку и построить новый»; в JS это `map`/`filter`:

```python
nums = [1, 2, 3, 4]
squares = [n * n for n in nums]              # [1, 4, 9, 16]       nums.map(n => n * n)
even    = [n for n in nums if n % 2 == 0]    # [2, 4]              nums.filter(n => n % 2 === 0)
index   = {c: i for i, c in enumerate("abc")}  # {"a": 0, "b": 1, "c": 2}
```

Именно так в `CharTokenizer` строится таблица «символ → номер»: `{c: i for i, c in enumerate(self.itos)}`.

**«Правдивость».** В условиях пустое считается ложью: `0`, `""`, `[]`, `{}`, `None`. Поэтому `if items:` значит «если список не пуст».

**Полезные встроенные функции:** `len`, `range`, `enumerate`, `zip` (склеить два списка попарно), `sorted`, `sum`, `min`, `max`, `any`, `all`, `isinstance`.

## 5. Функции

```python
def add(a, b=10):            # b необязателен, по умолчанию 10
    return a + b

add(1)                       # 11
add(1, 2)                    # 3
add(a=1, b=5)                # 6 — можно передавать по имени
```

- Вместо `function` — `def`, вместо фигурных скобок — двоеточие и отступ.
- Аргументы можно называть при вызове (`add(a=1, b=5)`). В нашем коде так вызывается почти всё: `train(steps=5000, lr=3e-3)`. Это читается лучше позиций.
- Значения по умолчанию — как в JS.
- Возврат нескольких значений — это кортеж: `return loss, accuracy`, а принимают через распаковку: `loss, acc = evaluate()`.

**Аннотации типов** — подсказки для людей и редакторов, интерпретатор их не проверяет:

```python
def encode(self, text: str) -> List[int]:
```

Читать: «принимает строку, возвращает список целых». Это как типы в TypeScript, только необязательные.

**`*args` и `**kwargs`** — «все остальные позиционные/именованные аргументы». Видно в `GPTConfig(vocab_size=vocab_size, **PRESETS[name])`: `**словарь` раскрывает словарь в именованные аргументы (как `...obj` в JS).

**Лямбда** — анонимная функция в одну строку: `lambda x: x * 2` (аналог `x => x * 2`).

**Генераторы и `yield`.** Функция с `yield` отдаёт значения по одному, не строя весь список. В нашем коде так перебираются файлы при сборке корпуса (`scripts/build_corpus.py`): путь к очередному `.md` выдаётся сразу, без построения списка всех файлов.

**Декораторы** (`@что-то` над функцией) — обёртки, меняющие поведение функции. В нашем коде три встречаются часто:

- `@classmethod` — метод принадлежит классу, а не объекту (см. раздел 6);
- `@property` — метод, который читается как свойство: `tok.vocab_size`, без скобок;
- `@torch.no_grad()` — «внутри этой функции не записывай градиенты» (экономит память при генерации).

## 6. Классы

```python
class Point:
    def __init__(self, x, y):     # конструктор
        self.x = x                # поля создаются присваиванием к self
        self.y = y

    def length(self):             # метод; первый аргумент ВСЕГДА self
        return (self.x ** 2 + self.y ** 2) ** 0.5

p = Point(3, 4)                   # создать объект: без new
p.length()                        # 5.0
```

- `self` — это `this` из JS, но его нужно писать явно первым аргументом каждого метода.
- `__init__` — конструктор. Имена с двойным подчёркиванием (`__init__`, `__call__`) — «магические» методы, особые для языка.
- Создание объекта — просто вызов класса: `Point(3, 4)`.

**Наследование.**

```python
class Block(nn.Module):           # Block наследует от nn.Module (скобки = родитель)
    def __init__(self, cfg):
        super().__init__()        # вызвать конструктор родителя (как super() в JS)
```

Все слои нашей модели — наследники `nn.Module` из PyTorch. Правило одно: в `__init__` вызвать `super().__init__()`, а метод `forward` описывает, что слой делает с данными.

**`@classmethod`** — «альтернативный конструктор», метод на уровне класса. Первый аргумент — не `self`, а `cls` (сам класс):

```python
@classmethod
def from_dict(cls, d):
    return cls(**d)               # создать объект из словаря
```

В JS это `static`.

**`@dataclass`** — генерирует `__init__` и прочее по списку полей, если класс нужен просто как контейнер данных. Так сделан `GPTConfig`:

```python
@dataclass
class GPTConfig:
    vocab_size: int = 256
    n_layer: int = 4
```

Это то же, что в JS писать `constructor({vocabSize = 256, nLayer = 4})` и присваивать поля вручную. Использование: `cfg = GPTConfig(n_layer=6)`; доступ — `cfg.n_layer`.

## 8. PyTorch: тензоры, слои, обучение

PyTorch — библиотека для нейросетей. Всё в ней строится на **тензорах**.

**Тензор** — многомерный массив чисел одного типа, с «формой» (shape). Похож на `Float32Array`, только многомерный и умеющий считаться на видеочипе.

```python
import torch
t = torch.tensor([[1., 2., 3.],
                  [4., 5., 6.]])
t.shape          # torch.Size([2, 3])  — 2 строки, 3 столбца
t * 2            # поэлементно: [[2,4,6],[8,10,12]]
t.sum()          # 21
t[0]             # первая строка
t[:, 1]          # второй столбец (двоеточие = «все»)
```

**Формы в нашей модели.** В комментариях везде встречаются буквы:

- `B` — размер батча (сколько кусков текста обрабатываем одновременно);
- `T` — длина текста в токенах;
- `C` — размер вектора на токен (`n_embd`).

Вход модели имеет форму `(B, T)`: `B` строк по `T` номеров токенов. После эмбеддингов — `(B, T, C)`: каждый номер превратился в вектор из `C` чисел. Если вы запутались, **выписывайте формы**: это главный способ понимать код нейросетей.

**Основные операции:**

| Операция | Смысл |
|---|---|
| `x.view(B, T, 4, 16)` | переставить размеры, не меняя данные (как разложить ту же колоду карт по-другому) |
| `x.transpose(1, 2)` | поменять местами два измерения |
| `a @ b` | матричное умножение (центральная операция нейросетей) |
| `torch.softmax(x, dim=-1)` | превратить числа в вероятности (сумма по последней оси = 1) |
| `x.masked_fill(mask, v)` | заменить значения там, где маска истинна |
| `torch.tril(...)` | нижний треугольник матрицы (нули выше диагонали) |

**Слои.** Слой — объект, который хранит *обучаемые числа* (веса) и умеет «применяться» к данным. Применяют, вызывая как функцию:

```python
layer = nn.Linear(128, 256)   # умножение на матрицу 128×256 и сдвиг
y = layer(x)                  # x: (..., 128) → y: (..., 256)
```

Основные слои в нашем проекте: `nn.Linear` (линейное преобразование), `nn.Embedding` (таблица «номер токена → вектор»), `nn.LayerNorm` (выравнивание масштаба чисел), `nn.Dropout` (случайно «выключает» часть связей при обучении — защита от переобучения).

**Класс-модель.** Собственная нейросеть — класс-наследник `nn.Module` с двумя методами:

```python
class MLP(nn.Module):
    def __init__(self, cfg):               # здесь создаём слои
        super().__init__()
        self.fc = nn.Linear(cfg.n_embd, 4 * cfg.n_embd)
    def forward(self, x):                  # здесь описываем, как данные проходят через слои
        return self.fc(x)
```

Вызов `mlp(x)` сам запускает `forward`.

**Как нейросеть учится — пять строк, на которых держится всё.** Цикл обучения (глава 6) выглядит так:

```python
logits = model(x)                    # 1. прогнать данные, получить предсказание
loss = F.cross_entropy(logits, y)    # 2. посчитать ошибку по сравнению с правильным ответом
optimizer.zero_grad()                # 3. сбросить старые градиенты
loss.backward()                      # 4. вычислить, как нужно изменить каждый вес (градиент)
optimizer.step()                     # 5. чуть-чуть поправить веса в нужную сторону
```

В `microllm/train.py` рядом есть ещё одна строка, `clip_grad_norm_`: она не даёт градиенту стать слишком большим. Повторить это много тысяч раз — и модель «учится». `loss.backward()` делает PyTorch сам: он помнит все операции и умеет считать производные автоматически (автоматическое дифференцирование).

**Устройство.** Вычисления можно выполнять на процессоре (`cpu`), видеокарте NVIDIA (`cuda`) или на чипе Apple (`mps`). Модель и данные должны быть на одном устройстве: `model.to("mps")`, `x.to("mps")`. Наш код сам выбирает лучшее доступное (`checkpoint.py`).

**Два режима.** `model.train()` включает dropout (обучение), `model.eval()` отключает его (проверка и генерация). `with torch.no_grad():` отключает запись градиентов, когда мы только читаем ответ модели: так быстрее и меньше памяти.

## 9. Разбор нашего кода: слой внимания

Файл `microllm/model.py`, класс `CausalSelfAttention`. Идею самого внимания объясняет глава 5 учебника; здесь — как читать код.

### 9.1. Конструктор

```python
class CausalSelfAttention(nn.Module):
    def __init__(self, cfg: GPTConfig):
        super().__init__()
        assert cfg.n_embd % cfg.n_head == 0, "n_embd должен делиться на n_head"
        self.n_head = cfg.n_head
        self.head_dim = cfg.n_embd // cfg.n_head
        self.qkv = nn.Linear(cfg.n_embd, 3 * cfg.n_embd)
        self.proj = nn.Linear(cfg.n_embd, cfg.n_embd)
```

- `class … (nn.Module)` — наследуем от базового класса слоёв.
- `cfg: GPTConfig` — аннотация: конфигурация, тот самый `@dataclass` из раздела 6.
- `assert … , "…"` — проверка: размер вектора должен делиться на число голов, иначе упасть с понятным сообщением. `%` — остаток от деления, `//` — целочисленное деление.
- `self.qkv = nn.Linear(C, 3*C)` — один слой, который за раз вычисляет три вектора для каждого токена: запрос Q, ключ K и значение V. `3 * cfg.n_embd` — потому что их три.
- `self.proj` — слой, который в конце собирает результаты всех голов обратно в один вектор.

### 9.2. Прямой проход

```python
    def forward(self, x, return_attn=False):
        B, T, C = x.shape
        q, k, v = self.qkv(x).split(C, dim=2)
```

- `B, T, C = x.shape` — распаковка кортежа: получаем три числа формы входа (раздел 8).
- `self.qkv(x)` — применяем слой. Результат имеет форму `(B, T, 3C)`.
- `.split(C, dim=2)` — режем по последней оси на три куска по `C`: получаем `q`, `k`, `v`, каждый `(B, T, C)`. Снова распаковка в три переменные.

```python
        q = q.view(B, T, self.n_head, self.head_dim).transpose(1, 2)
```

Делим вектор из `C` чисел на `n_head` частей по `head_dim` (так появляются «головы» — параллельные независимые «взгляды») и переставляем оси так, чтобы голова стала отдельным измерением: `(B, головы, T, размер_головы)`. То же для `k` и `v`.

```python
        att = (q @ k.transpose(-2, -1)) / math.sqrt(self.head_dim)
```

`@` — умножение матриц: для каждой пары токенов считаем «насколько запрос одного подходит к ключу другого». Получается матрица `T × T` на каждую голову: «кто на кого смотрит». Деление на корень из `head_dim` не даёт числам вырасти слишком большими. `transpose(-2, -1)` — поменять две последние оси (отрицательные номера считаются с конца, как индексы списка).

```python
        att = att.masked_fill(self.mask[:, :, :T, :T] == 0, float("-inf"))
```

Закрываем «будущее»: токен не должен подглядывать вперёд, иначе обучение было бы обманом. `self.mask` — нижняя треугольная матрица из единиц; где она равна 0 (выше диагонали), ставим `-inf` (минус бесконечность), и после softmax эти места превратятся в нули. `[:, :, :T, :T]` — срез: берём левый верхний угол `T × T`.

```python
        att = F.softmax(att, dim=-1)
```

Каждую строку превращаем в вероятности (сумма = 1). Это и есть **веса внимания**.

```python
        y = att @ v
```

Смешиваем значения `v` с этими весами: каждый токен получает «среднее» из тех токенов, на которые смотрел.

```python
        y = y.transpose(1, 2).contiguous().view(B, T, C)
        y = self.resid_drop(self.proj(y))
        return y, (weights if return_attn else None)
```

Собираем головы обратно в вектор `(B, T, C)`, пропускаем через `proj` и dropout. Последняя строка: вернуть пару — результат и (если попросили) веса внимания для картинок. Запись `A if условие else B` — тернарный оператор (в JS `условие ? A : B`).

### 9.3. Как прочитать любой кусок самостоятельно

1. Найдите строки, которые создают слои (`nn.…`) — это «детали».
2. В `forward` идите сверху вниз и для каждой строки выписывайте форму данных.
3. Незнакомую функцию (`split`, `view`) проверьте в консоли Python на маленьком примере: `torch.arange(12).view(3, 4)`.

## 10. Шпаргалка: JS ↔ Python

| Нужно | JavaScript | Python |
|---|---|---|
| Переменная | `let a = 1` | `a = 1` |
| Условие | `if (a) { … } else if (b) { … }` | `if a: … elif b: …` |
| Не равно | `!==` | `!=` |
| И, или, не | `&&`, `\|\|`, `!` | `and`, `or`, `not` |
| Пусто | `null` | `None` |
| Печать | `console.log(x)` | `print(x)` |
| Шаблон | `` `a ${b}` `` | `f"a {b}"` |
| Длина | `a.length` | `len(a)` |
| Добавить в массив | `a.push(x)` | `a.append(x)` |
| Срез | `a.slice(1, 3)` | `a[1:3]` |
| Последний | `a.at(-1)` | `a[-1]` |
| map | `a.map(x => x * 2)` | `[x * 2 for x in a]` |
| filter | `a.filter(x => x > 1)` | `[x for x in a if x > 1]` |

| Цикл | `for (let i = 0; i < n; i++)` | `for i in range(n):` |
| Класс | `class A { constructor() {} }` | `class A: def __init__(self): …` |

| static | `static f() {}` | `@classmethod` / `@staticmethod` |
| Исключение | `throw new Error("x")` | `raise ValueError("x")` |
| try/catch | `try {} catch (e) {}` | `try: … except Exception as e: …` |

| Spread | `{...obj}` / `f(...arr)` | `{**d}` / `f(*arr)` |

## 11. Частые ошибки

- **`IndentationError`** — неправильный отступ. Не смешивайте пробелы и табуляцию; везде по 4 пробела.
- **`ModuleNotFoundError: No module named 'torch'`** — вы запустили не тот Python (системный, а не из `.venv`). Используйте `.venv/bin/python` или активируйте окружение.
- **`ModuleNotFoundError: No module named 'microllm'`** — запускаете скрипт не из корня проекта. Перейдите в корень (папка, где лежат `microllm/` и `scripts/`) или добавьте корень в путь, как сделано в `scripts/check_rust_parity.py`.
- **`TypeError: unsupported operand type(s) for |`** — в Python 3.9 нельзя писать `str | None` в аннотациях без строки `from __future__ import annotations` в начале файла.
- **`UnicodeDecodeError`** — открыли файл без `encoding="utf-8"`.
- **`RuntimeError: mat1 and mat2 shapes cannot be multiplied`** — форма тензора не та, что ждёт слой. Выпишите формы по шагам и найдите, где они разошлись.
- **Модель и данные на разных устройствах** (`Expected all tensors to be on the same device`) — переложите всё на одно: `.to(device)`.
- **Изменяемое значение по умолчанию.** Не пишите `def f(a=[])`: этот список будет общим при всех вызовах. Принято писать `a=None` и внутри `a = a or []`.
